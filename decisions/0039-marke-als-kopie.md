# 0039 Die Marke kommt als Kopie ins private Repository, Grafiken und Website lesen sie

- Frage: Wie kommen die Farben und die Schrift der bitz Marke in die Grafiken der Ausgaben und in die Website, und wie kommt `_brand.yml` aus `bitzgmbh/brand` in das private Repository `bitzgmbh/newsletter`?
- Optionen: eine Kopie mit einem Skript, das sie holt und den Commit festhält; ein Git Submodul; die Quarto Erweiterung aus `bitzgmbh/brand`; eine Datei an einem Release.
- Wahl: Die Kopie. `scripts/marke-holen.sh` im privaten Repository holt `_brand.yml`, `logos/` und `assets/avatar.png` aus dem lokalen Clone von `bitzgmbh/brand` und schreibt den Commit nach `marke-stand.txt`; mit `--pruefen` vergleicht es nur. Die Website liest die Marke über `brand: _brand.yml` in `_quarto.yml`, das Theme bleibt `[litera, brand]`, und `styles.css` blendet die statische Grafik der Mail (`.nur-mail`) auf der Website aus. Die Grafiken lesen die Marke über eine Datei für alle Ausgaben, `R/marke.R`: Gruppen bekommen `chart-1` bis `chart-5` in dieser Reihenfolge, geordnete Stufen den Verlauf von `seq-low` bis `seq-high`, Text steht in `foreground`, die Quelle in `secondary`. Die Grafik für die Mail hat einen weissen Hintergrund, die für die Website keinen. Fehlt die Schrift der Marke und lässt sie sich nicht laden, bricht das Rendern mit einer Meldung ab; eine Ersatzschrift gibt es nicht. Der Skill grafiken und seine Vorlage tragen diese Regeln und keinen festen Farbwert mehr. Die Ausgaben vom 12. und 26. November 2026 behalten ihre eigene `marke.R`. Versendete Ausgaben werden nicht neu gerendert.
- Warum: Die Kopie rendert heute, ohne dass die GitHub Action Zugriff auf ein zweites privates Repository braucht. Ein Submodul verlangt dafür ein Token und einen Schritt mehr bei jedem Clone. Die Erweiterung trägt bisher nur das Format für Typst und kopiert beim Installieren ebenfalls Dateien. Releases gibt es in `bitzgmbh/brand` nicht. Dass eine Kopie veralten kann, fängt der festgehaltene Commit auf. Ein Abbruch bei fehlender Schrift ist besser als ein Bild in der falschen Schrift, das eingefroren in die Mail geht.
- Stand des Issues: Der Text von Issue 5 beschreibt Version 1 der Marke (Teal Familie, IBM Plex Sans). Seit dem 4. November 2026 gilt Version 2: Atkinson Hyperlegible Next und Mono, Waldgrün mit Bernstein, graues Papier am Bildschirm und Weiss für Druck und Mail. Die Token `bitz-teal-*` gibt es nicht mehr. Die Schrift ist auf meinem Rechner installiert und muss nicht im Chunk geladen werden.
- Offen: die Erweiterung als Weg, sobald eine zweite Website die Marke braucht; die Schriftdateien selbst ausliefern statt über Google Fonts, sobald die Website unter einer eigenen Domain läuft (0027).
